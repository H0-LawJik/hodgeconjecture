## Findings

1. **Statement unchanged.** The diff of `SimplicialCochainSpan.lean` against main touches the module docstring and the docstring of `SimplicialComplexSpan` only; status word "stated" becomes "checked" and the proof plan paragraph now describes the projection route. The `Iff.rfl` test against main's verbatim text confirms the `Prop` is the same term. The new docstring is accurate: `P = Σ ratScaled wᵢ ∘ λᵢ` is the identity on `W`, and Baer is applied to `ℂ` itself.

2. **Correct unconditional theorem.** Ledger title of `de-rham-rational-span`: "Submodule.span ℂ (Set.range (fieldToDeRhamCohomology ℚ X n)) = ⊤ for projective X". `span_range_fieldToDeRhamCohomology_rat` has exactly this conclusion, for explicit `X : Over (Spec ↧ℂ)` with `[IsIntegral X.left] [Smooth X.hom] [IsProjective X.hom]` and explicit `n : ℕ`, the binders of `DeRhamRationalSpan`; it is `deRhamRationalSpan X n`. `deRhamRationalSpan` is `deRhamRationalSpan_of_simplicialComplexSpan simplicialComplexSpan`, so no hypothesis remains. Field-by-field comparison with the literature (surjectivity half of `ℂ ⊗_ℚ H^n(X; ℚ) ≅ H^n_dR(X)`, [Hatcher2002] for universal coefficients, section unverified) is in finding 1 of the earlier red team and still applies: the statement did not move.

   `simplicialComplexSpan` against the literature: for a simplicial set `Y` and a `ℚ`-vector space `A`, `H^n(Y; A) ≅ Hom(H_n(Y; ℤ), A)` because `Ext(H_{n−1}, A) = 0` for divisible `A` ([Hatcher2002], universal coefficient theorem, section unverified). With `H_n(Y; ℤ)` finitely generated, `Hom(H_n, ℂ) = Hom(H_n, ℚ) ⊗_ℚ ℂ`, so every complex class is a finite sum `Σ zᵢ βᵢ` with rational `βᵢ`. The Lean form: `zᵢ βᵢ` is `(ratScaled zᵢ)_* βᵢ`, the push along the port's `linearDualCoefficientChange`, and the finite sum is membership in `AddSubgroup.closure (⋃ z, range (ratScaled z)_*)`. Only `H_n` needs to be finitely generated, which is the hypothesis in the statement.

3. **Degree 0.** In `homologyMap_linearDualCoefficientChange_eq`, case `zero` (lines 300 to 311): for each `0`-simplex `x`, `exists_cycles_of_d_eq_zero Kℤ 0 0 ChainComplex.next_nat_zero` produces an integral cycle with image `chainOfSimplex ℤ Y 0 x`, the kernel condition discharged by `Kℤ.shape 0 0`. Both are sound: `(ComplexShape.down ℕ).next 0 = 0` because nothing maps `0` to a lower index, and `d 0 0 = 0` because `¬ (ComplexShape.down ℕ).Rel 0 0` (`0 + 1 ≠ 0`); both facts were rechecked in scratch. Hence `f = (P)_* c − c` vanishes on every `0`-simplex, `f = 0` by `dualToFun_injective`, and the witness `w = 0` is right. Mathematically, `H^0(Y; ℂ)` is the space of functions on simplices with `c ∘ ∂₁ = 0`, and `P ∘ c = c` pointwise because every integral `0`-chain is a cycle, so its values lie in `W`. The degree-0 case of the statement holds as stated.

4. **The Baer step.** `exists_dualMap_d_eq_of_cochainEval` (lines 126 to 167). The hypothesis says `φ = eval f` vanishes on `ker(∂ : C_{k+1}(Y; ℤ) → C_k(Y; ℤ))`, so `φ` factors through `C_{k+1} ⧸ ker ∂ ≅ range ∂` (`QuotientAddGroup.lift` and `quotientKerEquivRange`). The factor `g₀ : range ∂ →+ ℂ` extends along the inclusion `range ∂ ⊆ C_k(Y; ℤ)` by `Module.Baer.of_divisible ℂ`, which needs only that `ℂ` is a divisible `ℤ`-module (`ℂ` is a `ℚ`-vector space); no freeness and no finiteness enter. The coboundary is in the right degree: `e` has degree `k`, the conclusion is `(d (k+1) k).dualMap e = f`, and the consumer turns it into a cocycle of degree `k + 1` with zero class through `D.toCycles k (k + 1)` and `toCycles_comp_homologyπ`. Sign: the port's `forgetDual_d_apply` states that the differential of the forgotten `linearDualCochainComplex` is `(K.d (n+1) n).hom.dualMap`, with no sign (conventions row "Singular coboundary"). A sign would only replace `e` by `−e`; the step's output is "`f` is a coboundary", insensitive to it. The equality `δe = f` is checked simplex by simplex through `intChainsLift_comp_d`.

5. **Coefficient change.** Every map that enters is additive only. `l i = ((b.coord i).comp π).toAddMonoidHom : ℂ →+ ℚ` with `π : ℂ →ₗ[ℚ] W` a left inverse of the inclusion; no ring-map or `ℂ`-linearity is assumed of it, and the port's `linearDualCoefficientChange` takes `f : R →+ S` since `betti-additive-naturality`. `w i = (b i : ℂ)`, so each generator used is `(ratScaled (w i))_* ((l i)_* [c])` with `(l i)_* [c]` a rational class, an element of the range of the posted `homologyMap (linearDualCoefficientChange (ratScaled z) Y) n` at `z = w i`. The closure in the statement is generated exactly by these ranges; the proof enters it by `AddSubgroup.subset_closure` on one range per index and `AddSubgroup.sum_mem`. The algebra `[c] = (P)_*[c] = Σᵢ (ratScaled wᵢ ∘ lᵢ)_*[c] = Σᵢ (ratScaled wᵢ)_*((lᵢ)_*[c])` uses `linearDualCoefficientChange_add`, `_zero`, `_comp` with Mathlib's `homologyMap_add`, `_zero`, `_comp`; the three local lemmas are proved on the function model through `dualToFun_injective` and are correct as stated (composition order `f` then `g` matches `g.comp f`).

6. **Finite generation is consumed.** The instance enters only in `exists_finiteDimensional_cochainEval_mem`, through `Module.finite_def.mp inferInstance`, giving a finite set `s` with `span ℤ s = range G` for `G : H_n(Y; ℤ) →ₗ[ℤ] ℂ`. Removing the binder makes the step fail to elaborate (table). The hypothesis is also necessary for the statement, so the conclusion is not trivially true. Let `Y` be the constant simplicial set on `ℕ`. Then `H_0(Y; ℤ) = ℤ^(ℕ)` and `H^0(Y; ℂ) = ℂ^ℕ`. Each generator `(ratScaled z)_* β` has all its values in `z ℚ`, so every element of the closure has values in a finite-dimensional `ℚ`-subspace of `ℂ`. The class `(1, π, π², …)` has `ℚ`-independent values, so it lies outside the closure. The finiteness hypothesis carries the content.

7. **Transparency and checks.** The three `set_option backward.isDefEq.respectTransparency false in` (lines 173, 271, 341) are elaborator options: they change which unfoldings `isDefEq` tries while elaborating, and the kernel rechecks every term, so they cannot make a false statement pass. They are also unneeded. With all three deleted, the module elaborates both as a `module` file and as a plain file, and the copy of `simplicialComplexSpan` has type `HodgeLadder.SimplicialComplexSpan` with the standard axioms. The sketch's justification, "same as the port's file", therefore explains nothing. Axiom lines: standard on all 17 new declarations (table) and on every declaration both ledger entries name (checker). Trivial proofs fail.

10. **Conventions.** Used: the singular coboundary (δφ = φ ∘ ∂, no sign; row present); the integral boundary of Mathlib's alternating face map complex (sign-insensitive here); `ratScaled z = q ↦ z q` (row "Change of coefficients along an additive map", present); evaluation of an `R`-valued cochain on integral chains (`cochainEval`, no row; **added** to `docs/conventions.md` as "Evaluation of a simplicial cochain on integral chains"); the choice of `ℚ`-basis and of the left inverse `π` (any choice works; no normalization). Truth does not depend on any of them. The statement is membership in an additive closure. It is unchanged by a sign on δ or ∂, and by any bijective reparametrization of `z ↦ ratScaled z` (conjugating `z`, scaling by a nonzero constant), because `z` ranges over all of `ℂ`. No result is cited or assumed: the Baer criterion is Mathlib's `Module.Baer.of_divisible`, and the port lemmas used (`intChainsLift_comp_d`, `forgetDual_d_apply`, `exists_cycles_of_d_eq_zero`, `dualToFun_dualCoefficientChange`) are checked Lean at the pin.
