## Findings

1. **Sign (attack 6), reported first: correct.** Read as a path with z the lower-left and w the upper-right corner, Mathlib's expression `∫ bottom − ∫ top + I • ∫ right − I • ∫ left` integrates the bottom side left to right (dp = dx), the right side upward (dp = I dy), the top side right to left (the minus sign reverses x from z.re to w.re) and the left side downward. That is the counterclockwise boundary, so the winding number convention (1/2πi)∮ dp/(p − a) = +1 predicts +2πi, the value the rung states. The same sign holds on circles: Mathlib's `circleMap c R θ = c + R·exp(θI)` runs counterclockwise and `circleIntegral.integral_sub_inv_of_mem_ball` gives +2πi, so the rectangle and circle conventions agree. Independent checks:
   - Probe P4 (Lean, scratch, compiles at the pin): `(∫ x in (-1)..1, ((x : ℂ) + (-1 : ℝ) * I)⁻¹).im = π / 2`, from Im (x − I)⁻¹ = (1 + x²)⁻¹, `ContinuousLinearMap.intervalIntegral_comp_comm` with `imCLM`, `integral_inv_one_add_sq`, `Real.arctan_one`. This avoids `Complex.log` and the candidate's side lemmas. On the square (−1 − I, 1 + I) the rotation p ↦ Ip carries each side onto the next one with its direction and preserves dp/p, so the four sides are equal; the real part of the bottom side is ∫ x/(1 + x²) over [−1, 1] = 0, so the total is 4 · (π/2) I = 2πI, matching `rectIntegral_inv_square`.
   - Midpoint sums (Python, 2·10⁵ points per side) of the literal four-term expression: z = −1 − 0.5i, w = 2 + 3i, a = 0.3 + 0.2i gives 6.2831853i; the square around 0 gives 6.2831853i; a = 2 + 0.5i outside (0, 1 + i) gives 0 to 10⁻¹¹.
   - The candidate's own telescoping, checked by hand: bottom log(q₁₀) − log(q₀₀), right log(q₁₁) − log(q₁₀), minus top log(q₀₁) − log(q₁₁) with sign reversed, minus left (log(−q₀₁) − log(−q₀₀)); the sum is (log(−q₀₀) − log q₀₀) + (log q₀₁ − log(−q₀₁)), with q₀₀ = z − a in the lower half-plane (πI by `arg_neg_eq_arg_add_pi_of_im_neg`) and q₀₁ in the upper (πI by `arg_neg_eq_arg_sub_pi_of_im_pos`). No branch crossing: bottom has Im < 0, top Im > 0, right Re > 0, and the left side uses log(a − p) with Re > 0, each inside the slit plane.

2. **Statement against the literature (item 1).** The winding number of a closed piecewise smooth curve γ about a ∉ γ is n(γ, a) = (1/2πi)∮_γ dz/(z − a), and the positively oriented boundary of a rectangle has n = 1 about each interior point (Ahlfors, Complex Analysis, ch. 4, unverified; no key in `docs/references.md`, and the sketch cites the same book as unverified). Field by field: the curve is Mathlib's four-term expression (definitionally, finding 3); the point is strictly interior (`z.re < a.re < w.re`, `z.im < a.im < w.im`); the value is 2πi with no scalar. The rung is the literature statement for rectangles.

3. **Definition (attack 1).** Probe P1: `rectIntegral f z w` equals Mathlib's left side by `rfl`, for `f : ℂ → ℂ`; the candidate's `rectIntegral_eq_zero_of_differentiableOn` also closes with the Mathlib term, for any `ℂ`-normed `E` with no completeness assumed (Mathlib states the rectangle theorems before its `variable [CompleteSpace E]`). A reordering of Mathlib's expression at a bump breaks the build here, which is the right failure mode. The definition is total: for other corner orders it is still defined, and Probe P3 proves `rectIntegral f w z = rectIntegral f z w` for every f (swapping both corners is a rotation by π and keeps the orientation), while the midpoint sum for z = 1, w = I, a = (1 + i)/2 (only the real parts swapped) gives −2πi. The hypotheses h₁ to h₄ fix the corner order, so the stated value is exact for the configuration they allow.

4. **Hypotheses (attack 2, item 2).** Satisfiable: `rectIntegral_inv_square` is an instance (a = 0, z = −1 − I, w = 1 + I) proved from the theorem. All four are used: h₃ and h₄ give the off-axis conditions of the horizontal sides and the half-planes of q₀₀ and q₀₁, h₁ and h₂ the slit-plane conditions of the vertical sides. Outside the rectangle the value is 0: Probe P2 proves `rectIntegral (fun p : ℂ ↦ (p - 2)⁻¹) 0 (1 + I) = 0` from `rectIntegral_eq_zero_of_differentiableOn` in five lines. So the theorem separates inside from outside.

5. **Vacuity (item 3, item 7b).** The conclusion is an equation with a nonzero right side, and `rectIntegral` is a genuine sum of interval integrals; no unfolding reaches `True`, no coercion, no empty type. The smallest test that fails if the value were trivial is P2 together with the rung (0 outside, 2πi inside); `rectIntegral_inv_square` is the candidate's in-tree instance. I failed to prove the statement in ten lines without the four side lemmas.

6. **`rectIntegral_sub_inv_ne_neg` is a corollary.** It follows from `rectIntegral_sub_inv` and π ≠ 0, so it adds no check of orientation beyond the main theorem; the orientation is fixed by the kernel-checked value +2πi itself. The test is the one the sketch asked for and is harmless, but the docstring phrase "which pins the orientation" and the ledger note "Orientation pinned by" overstate it (required change 3). Probe P4 would be an independent orientation test (optional change O1).

7. **Equality first (item 7).** The rung is an identity, proved exactly with value 2 * π * I, no scalar and no "up to sign".

8. **Fit with `rect-argument-principle` (attack 3).** The consumer's step "integrate" needs, beyond this rung: (a) linearity of `rectIntegral` over a finite sum Σ d u · (p − u)⁻¹ + logDeriv g, which needs interval integrability of each summand on each side (continuity on the boundary suffices); (b) a congruence lemma: if f = g on the boundary `[[z.re, w.re]] ×ℂ [[z.im, w.im]] \ (Ioo z.re w.re ×ℂ Ioo z.im w.im)` then `rectIntegral f z w = rectIntegral g z w`, because `logDeriv f` agrees with the partial-fraction form only near the boundary (`MeromorphicOn.logDeriv_finprod_zpow_eventuallyEq` is an eventual equality). Neither is in this rung or in Mathlib at the pin (no `rectIntegral` exists there); both are short. The interior case matches exactly: `u ∈ Ioo z.re w.re ×ℂ Ioo z.im w.im` unfolds to the four strict inequalities h₁ to h₄. Points u of the open neighbourhood U outside the closed rectangle go through `rectIntegral_eq_zero_of_differentiableOn` as in P2. The consumer's statement fixes z lower-left by `hre`, `him`, the same order as here, so the sign carries over with no flip. Required change 4 records (a) and (b) on the consumer's note.

The direct proof by four logarithm differences is the shortest route, and the local copy is justified under decision 0011.
